## 一、项目全貌

| 端 | 用户 | userType | 核心职责 |

## 二、现状 vs 文档：必须先对齐的 8 个问题

这是最重要的一节。**不解决这些，各人写各人的，最后合不到一起。**

### 问题 1（最严重）：MyBatis-Plus 没装，但文档全是 MP 写法

- `pom.xml` 里是原生 `mybatis-spring-boot-starter:4.0.1`
- `entity.md` 里写了 `mybatis-plus.global-config.db-config.logic-delete-field: isDeleted`、设计说明里写了 `IdType.ASSIGN_ID`（雪花算法）
- 结果：**逻辑删除不会自动生效，主键不会自动生成**

> 建议（二选一，推荐 A）
> - **A. 不引入 MP**：SQL 里每个查询自己带 `AND is_deleted = 0`，主键改成数据库自增。改动小、可控，实训项目够用。
> - B. 引入 `mybatis-plus-spring-boot3-starter`，统一用 MP 的 `BaseMapper` + 逻辑删除。但 Boot 4 兼容性要自己验证，风险高。
>
> **决定了请全队统一，写在 README 里。**

### 问题 2：主键 BIGINT 但不是自增，也没生成器

`yiyang.sql` 里所有表都是 `id BIGINT NOT NULL`，**没有 AUTO_INCREMENT**，而项目里又没有雪花算法。

> 修：给所有表补自增（见文末 SQL 补丁）。

### 问题 3：包名三套并存

| 东西 | 文档写的 | 代码实际 |
|---|---|---|
| 实体 | `com.cdut.entity` | `com.cdut.pojo` |
| Result | `com.cdut.common.Result` | `com.cdut.pojo.Result` |
| Controller | `com.cdut.controller` | `com.cdut.controller` ✅ |

> 修：全队统一。**建议跟代码走用 `com.cdut.pojo`**（改动最小，现有 4 个 pojo 不用动），或者队长拍板全部迁到 `com.cdut.entity`。

### 问题 4：分页没方案，但接口全是 `PageInfo`

接口文档出参写的是 `Result<PageInfo<Xxx>>`（PageHelper 的类），但 `pom.xml` **没有 PageHelper**，也没有 MP 的分页插件。

> 修（二选一）
> - 引入 `pagehelper-spring-boot-starter`（跟文档对齐，改动最小）
> - 或统一改成自定义 `PageResult<T>` 手写 `limit/offset`
>
> 无论哪种，**分页返回体必须统一**：`{total, pages, pageNum, pageSize, list}`

### 问题 5：密码没加密方案

`ElderAccount.password` 注释写着"密码（加密）"，但项目里没有任何加密依赖（无 spring-security-crypto、无 hutool、无 commons-codec）。

> 修：加 `spring-security-crypto`，用 `BCryptPasswordEncoder`。**注册写入时加密，登录时用 `matches()` 比对。** 不要自己写 MD5。

### 问题 6：拦截器没启用 + 有 bug

`WebConfig.addInterceptors()` 整段被注释掉了，目前**所有接口裸奔**。

`LoginInterceptor` 的两个问题：
1. `claims.get("userId", String.class)` —— JJWT 存进去的是 Long/Integer，用 `String.class` 取会抛 `RequiredTypeException`，等于**必然解析失败**。要改成 `claims.get("userId", Long.class)` 或统一存 String。
2. 失败时直接 `response.getWriter().write("Token无效或已过期")`，**返回的是纯文本不是 Result JSON**，前端会解析失败。要改成输出 `{"code":500,"message":"..."}`。

> 另外：拦截器目前只放 `userId`，**没放 userType**。老人端和医生端路径都走 `/api/**`，必须带 userType 才能做端隔离，否则医生 token 能调老人接口。

### 问题 7：全局异常处理返回的不是 Result

`GlobalExceptionHandler` 返回 `ResponseEntity<String>`，直接把异常栈信息甩给前端。

> 修：改成返回 `Result`，并且**补一个参数校验异常处理器**（`@Validated` 失败时现在会走兜底分支）。

### 问题 8：文档内部自相矛盾

| 冲突点 | 说明 |
|---|---|
| 响应码 | `entity.md` 示例里有 `Result.error(2002, "...")`，但 `接口文档.md` 明确"只有 200/500"。**以接口文档为准**（现有 `pojo/Result` 的 `error(String)` 就是对的，别改成带 code 的版本） |
| `elder_family_binding` | `entity.md` 说"无独立实体"，但接口文档 `/api/elder/family/bindings` 出参是 `List<ElderFamilyBinding>`。**得建实体** |
| 验证码 | 接口文档写了 `captcha` / `captchaKey` 参数，但**没有定义验证码接口**。要么补一个 `GET /api/auth/captcha`，要么全队约定先不做（前端不传） |
| refreshToken | `LoginRespDTO` 有 `refreshToken`，但**没有刷新接口**。建议先返回和 accessToken 一样的值，或约定不做 |
| 医生端登录账号 | `接口文档` 医生登录用 `phone`，`entity.md` 的 `LoginDTO` 用 `username` + `userType`。要统一 |

## 四、建议的全队统一约定（让队长拍板）

1. **包结构**：`pojo`(实体) / `dto` / `mapper` / `service`+`service.impl` / `controller` / `config` / `interceptor` / `common` / `utils`
2. **Controller 路径**：管理端 `/api/admin/**`、医生端 `/api/doctor/**`、老人端 `/api/elder/**`（接口文档里老人端"我的档案"和"个人中心"都挂在 `/api/elder/profile`，建议**个人中心拆到 `/api/elder/center/**`** 避免和档案模块撞路径 —— 见个人规划文档）
3. **返回体**：`Result<T>`，只有 200/500
4. **分页**：PageHelper 的 `PageInfo`，统一 `{total,pages,pageNum,pageSize,list}`
5. **主键**：数据库自增
6. **逻辑删除**：手写 `AND is_deleted = 0`
7. **密码**：BCrypt
8. **Token**：JWT，Header `Authorization: Bearer xxx`，payload 至少含 `userId`、`userType`
9. **当前用户获取**：`UserContext.getUserId()`（ThreadLocal），**Controller 里不再用 `request.getAttribute`**
10. **时间字段**：`LocalDateTime` / `LocalDate`，靠 `map-underscore-to-camel-case` 自动映射（已开启 ✅）
